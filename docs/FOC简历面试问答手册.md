## 第 1 部分：FOC 基础（对应简历第 1 条）

### Q1. 什么是 FOC？一句话

**答：** 把三相交流电流，通过两次坐标变换变成两个**直流**分量（id、iq），然后用 PI 分别控制它们，最后再变换回三相电压输出。

**核心动机一句话：** 「PI 控不好交流量，但控直流量很完美。FOC 就是想办法把交流问题变成直流问题。」

### Q2. Clarke 变换的公式？为什么要变？

**答：** 三相电流 ia、ib、ic 满足 `ia + ib + ic = 0`，所以三个量里只有两个是独立的。Clarke 把三相压成两相正交：

```
iα = ia
iβ = (ia + 2·ib) / √3
```

**为什么变：** 三个 120° 的分量不方便算，两个正交分量（α、β）才是标准坐标系。

**追问：分母为什么是 √3 不是 √3/2？**
> 因为这是**等幅值**变换。等功率变换才会出现 √3/2 的系数。我用的等幅值，所以 iα 直接等于 ia。

### Q3. Park 变换的公式？为什么还要变？

**答：**

```
id =  iα·cosθ + iβ·sinθ
iq = −iα·sinθ + iβ·cosθ
```

**为什么变：** αβ 坐标系是静止的，里面的电流还是随转子转的正弦量。用转子电角度 θ 把它旋转到转子上，稳态时 id、iq 就是**直流**了。

**追问：id 和 iq 分别代表什么？**
> - **id 是励磁分量**（建立磁场），表贴式永磁电机不需要弱磁，所以**目标给 0**；
> - **iq 是转矩分量**，转矩 T ∝ iq，所以 **iq 就是"转矩指令"**。

### Q4. SVPWM 有哪两种实现？为什么选共模注入？

**答：** 两种——**判扇区算作用时间**，和 **min-max 共模注入**。数学上等价。

**共模注入的做法：**

```
1. 反 Park 得到 uα、uβ
2. 反 Clarke 得到三相电压 ua、ub、uc
3. 找出 umax 和 umin
4. 注入共模量 = −(umax + umin) / 2
5. 三相各加这个共模量 → 转成占空比
```

**为什么选它：** 不用判断扇区、不用算三角函数作用时间，**省 CPU**。一个 20 kHz 中断里能省几十条指令。

**追问：为什么共模注入能提高电压利用率？**
> 纯正弦调制时，相电压最大只能到 **Vdc/2 = 6 V**；注入共模（零序）后可以到 **Vdc/√3 = 6.93 V**，多 **15.5%**。
> 原因：共模量在三相里是**相同的**，相减成线电压时被抵消掉，所以线电压还是纯正弦，电机不受影响。

**追问：为什么占空比是"马鞍波"？**
> 共模注入后每相的波形不再是正弦，峰顶和谷底各有一个浅凹 —— 这是 SVPWM 的**正常结果**，不是 bug。凹深约 1.55% 占空比。

### Q5. 你的 PWM 怎么配的？

**答：**

```
TIM1，中心对齐（Center-Aligned）
预分频 PSC = 0，自动重装 ARR = 4199
168 MHz ÷ (4199+1) ÷ 2（中心对齐）= 20 kHz → 周期 50 µs
重复计数器 RCR = 1
```

**追问：RCR 是什么？为什么是 1？**
> RCR = Repetition Counter。中心对齐下计数器 0→4199→0 一个往返，**只有回到 0 才产生一次更新事件**。RCR=1 表示"每两次折返才产生一次"，所以中断频率就是 20 kHz。如果 RCR=0 就变 40 kHz，角度会快一倍。

**追问：为什么用中心对齐而不是边沿对齐？**
> ① 三相 PWM 的开关时刻对称，**电流纹波更小**；② 采样时刻落在峰顶时三相下桥同时导通，**便于低侧电流采样**。

**追问：为什么不开互补输出（CHxN）？**
> 两块驱动板（L6234 / FD6288）都是**每相一路单端 PWM 输入**，上下桥互补和死区在**芯片内部**产生。我要是开了 CHxN，就变成外部的两路信号打架了。

## 第 2 部分：编码器与极对数（对应简历第 2 条）

### Q6. MT6701 怎么读的？

**答：**

```
接口：SPI1，配置成 Full-Duplex Master
      DataSize 8bit、CPOL=Low、CPHA=1Edge、NSS=Soft、MSB First
时钟：84 MHz ÷ 16 = 5.25 MHz
片选：PA4 手动拉低/拉高
读法：拉低 CS → 读 2 个字节 → 拉高 CS → 拼成 14 位角度
```

**追问：为什么分频 16？**
> 默认 ÷2 = 42 MHz，MT6701 手册上限大概十几 MHz，42 MHz **完全读不出数据**（返回全 0 或乱码）。÷16 后 5.25 MHz 就稳了。

**追问：为什么只接 3 根线（CS/SCK/MISO）？**
> 因为是 **SSI 单向只读**协议，只需要读、不需要写，MOSI 根本不用接。

### Q7. 速度怎么算的？

**答：** 差分测速 —— 固定时间窗口内取角度差：

```
speed = (angle_now − angle_last) / Δt
```

再配一阶低通滤波平滑。

**追问：为什么不直接用编码器芯片的速度寄存器？**
> MT6701 的 SPI 模式只给角度，不给速度。而且差分测速的时间窗口我自己能控，可以按需要调平滑程度。

**追问：测速的难点是什么？**
> **延迟和噪声的取舍**。窗口太小 → 噪声大（一个计数跳变就抖）；窗口太大 → 延迟大（速度环会震荡）。我一开始用 5 ms 窗口 + 25 ms 低通，总延迟 30 ms，速度环怎么调都震；后来压到约 6 ms 就好了。

### Q8. 「极对数误填 + 每圈计数误填两个 2 倍错误互相抵消」——这句话讲清楚

**这是你简历里最有含金量、也最容易被追问的一句。**

**答（按顺序讲）：**

```
现象：开环给定 1.0 rad/s，实测只有 0.23~0.48（一直丢步）；位置环能顶住但推开回不来。

第一步怀疑极对数。用"开环速度比值法"验证（实测/给定 ≈ 1.0 即正确），
算出比值 1.06 → 反推极对数 21，改成 21 后当晚怪现象消失。

但闭环还是不对。继续查，发现第二个错：
MT6701 是 14 位，原始字段 0~16383，但它要转【两整圈】才填满
→ 每机械圈实际只有 8192 个计数，而我填的是 16384。

后果：所有角度和速度都只有真实值的一半。

关键：这两个错误互相抵消！
  极对数错 2 倍（21 实际 10）× 计数错 2 倍（16384 实际 8192）
  = 21/10 × 16384/8192 ≈ 1.05
  → 用"21 对极 + 16384 刻度"算出的比值恰好是 1.05，看起来"差不多对了"
  → 骗了整整两天

破解：找一个【不依赖编码器】的绝对参考——秒表。
  开环转满 10 圈计时，T 应该 = 62.83 / 目标转速(rad/s)
  时间不会说谎，60 秒定案：真实是 10 对极、每圈 8192。
```

**追问：怎么确认「每圈 8192」这个数？**
> 最直接的办法：`ENC_TEST_MODE=1` 只读编码器，手转**一整圈**，看角度是否走满 0→6.283。如果只走到 3.14，就是刻度错了一倍。

**追问：为什么会出现"21"这个假象？**
> 因为我在用错误的刻度算速度，等于把两个 2 倍误差乘在一起，结果落在 1.0 附近。**所有间接测量都自洽地错着，互相验证反而是错的。**

## 第 3 部分：电角度零位标定（对应简历第 3 条）

### Q9. 为什么要标 offset？

**答：** 编码器读的是**机械角**，而 FOC 需要知道**转子 d 轴相对 A 相的真实电角度**。两者差一个固定的相位偏移，就是 offset。不标定 → 电压矢量方位错 → 转矩小甚至为 0。

**追问：错了会怎样？**
> 差 180°：电机完全没力气（矢量对着反向）。
> 差 90°：电流很大、芯片发烫，但**转矩 ≈ 0**，电机一动不动 —— 这个现象我遇到过，一开始以为是"力不够"，其实是对着 d 轴。

### Q10. 「固定矢量预定位」怎么做？

**答：**

```
1. 给一个固定的电压矢量（theta = θ0，Uq 给固定值）
2. 转子会被吸到一个固定位置（d 轴对齐到这个矢量方向）
3. 读此时编码器的机械角 mech
4. 那么 offset = θ0 + π/2 − mech × 极对数
```

**追问：为什么有个 π/2？**
> 因为给 Uq 时，实际电压矢量加在 **θ0 + 90°** 方向（Park 反变换里 q 轴超前 d 轴 90°）。转子 d 轴会停在电压矢量方向，所以是 θ0 + π/2，不是 θ0。

**追问：怎么验证标对了？**
> **自洽校验**：把标出来的 offset 代回去，算 `mech × 极对数 + offset`，结果应该落回 **θ0 + π/2** 附近（折到 0~2π）。两次上电测出来差不到 0.05 rad 就可信。

### Q11. 「offset 自动扫描」是什么？

**答：** 让 offset 每 100 ms 递增 0.04 rad 转一整圈，同时位置环一直开着。当 offset 扫过正确值时，电机会突然朝目标方向走 —— 那个点就是正确值。适合"完全不知道 offset 在哪"的冷启动。

## 第 4 部分：闭环为什么都是纯 P（对应简历第 4 条）

**⚠️ 这是最能体现你踩过坑的一段，也是最能加分的一段。要背熟数字。**

### Q12. 为什么位置环用纯 P，不加积分？

**答：** 加过，但**震荡**。原因不是参数没调好，是物理限制。

```
这台电机 Kt ≈ 0.0099 N·m/A，1A 只有 10 mN·m，转矩极软。
静摩擦和齿槽就要这个量级。

所以误差很小时（比如 0.1°），P 项给出的电压推不动静摩擦 → 误差一直存在
→ 积分不停累积 → 累积到能推动的那一刻，已经是满力 1.3V
→ 猛冲过头 → 误差反号 → 反向再来一次
→ 变成开关控制（bang-bang），疯狂震荡

实测：误差只有 0.023 rad（1.3°）时，输出电压已经顶在 −1.300 V 限幅上，
说明积分早就涨满了。
```

**结论：接受 3° 左右的稳态误差，换掉震荡。**

**追问：那如果一定要消掉稳态误差怎么办？**
> 用**摩擦前馈**，不用积分：
> ```c
> if (error >  0.005) ff =  0.15f;
> if (error < -0.005) ff = -0.15f;
> voltage = Kp * error + ff;
> ```
> 区别：前馈是**固定值**，永远不会积到满力；积分是**累加器**，一定会涨满。

### Q13. 速度环的 V/f 前馈是什么？斜率怎么定的？

**答：** 前馈给出"维持这个转速大概需要多少电压"，P 只负责修补误差。

```
Uq_feedforward = 斜率 × 电角速度 + 摩擦补偿
               = 0.0011 × (10 × 机械转速) + 0.05
```

**斜率怎么定的（重点，体现方法）：**

```
步骤 1：先随便给一个前馈，跑闭环，记录一个稳定点
        实测 Uq = 0.106 V 时转速 10 rad/s
步骤 2：从这个点反推
        Uq ≈ 摩擦电压 + Ke × ω
        0.106 ≈ 0.05 + Ke × 10
        → Ke ≈ 0.0106 V/(rad/s)
步骤 3：换算成电角速度（×10 对极）
        Uq = 0.00106 × we + 0.05
```

**追问：之前标错是什么样？**
> 一开始按**开环**数据标，斜率给成 0.0020，多给了一倍多。结果 P 项必须拼命反向补偿 → 补偿不够就超速、补偿过头就震荡。**把前馈标准后，误差趋近 0，P 几乎不出力，震荡自己就消失了。**

**追问：为什么开环标的数据不能用？**
> 因为开环时转子一直打滑。实测：开环 0.363 V 只能跑 0.48 rad/s；闭环 0.101 V 就能跑 6.83 rad/s —— **效率差 20 倍**。所以开环标的 V/f 全都偏高。

## 第 5 部分：热设计（对应简历 "I²R 损耗"）

### Q14. 电压-温升安全表怎么来的？

**答：** 两步 —— 算 + 摸。

```
算：芯片损耗 = 3 × I² × Rds(on)
    L6234 的 Rds(on) ≈ 0.3 Ω（单个 MOS），上下管串起来约 0.6 Ω

实测温度（手摸，无散热片）：
    0.7 V → 温
    1.0 V → 烫但能摸
    1.3 V → 接近上限
    2.0 V → 明显发热，不可持续
```

**追问：为什么开环时特别烫，闭环反而不烫？**
> 因为**低速时反电动势几乎为 0，给的电压全部压在电阻上变成电流和热**。
>
> | 状态 | 转速 | Uq | 反电动势 | 电流 | 芯片损耗 |
> |---|---|---|---|---|---|
> | 早期开环 | 0.5 rad/s | 1.64 V | 0.005 V | 3.0 A | **8.1 W** |
> | 现在闭环 | 10 rad/s | 0.106 V | 0.099 V | ~0.01 A | **≈0 W** |
>
> 同样是这块芯片同一个电机，只是工作点从"低速硬推"变成"高速滑行"。

## 第 7 部分：三个"必被问到"的通用问题

### Q15. 这个项目最难的地方是什么？

**答（选一个讲深）：**

> **最难的不是写 FOC 公式，而是"反馈是错的"这件事你怎么发现。**
>
> 我卡了两天，因为极对数和编码器刻度各错了一倍，两个错误互相抵消，**所有间接测量都自洽地错着**。用速度比值法验证，比值是 1.05，看起来完全对。
>
> 最后是靠"秒表转 10 圈计时"这个不含任何传感器的绝对参考才定案。这件事之后我养成一个习惯：**当两个以上关键参数都可能错时，一定要找一个不含被污染传感器的物理量来交叉验证。**

### Q16. 你现在还差什么没做完？

**答（诚实且具体）：**

> **电流环没做完。** 现在是三层"电压模式"——开环 V/f、位置环、速度环，输出的都是电压，没有一层知道实际电流。
>
> 硬件我已经打通了：换的驱动板上有 4 颗 INA240 做两相 inline 采样，实测零电流输出 1.65 V、换算 0.5 V/A，已经接到 ADC 并验证了零点。软件还差 Clarke→Park→id/iq 双 PI 这一段，以及把 ADC 的软件触发升级成定时器硬件触发。
>
> **缺了电流环的后果是**：限流只能限电压（1.3 V），实际上是在"猜"电流；而且低速时一旦反电动势小，电流就失控。

### Q17. 为什么用这台电机？为什么效果一般？

**答（转成加分项）：**

> 这是我一开始买的云台电机，实测 0.36 Ω/相、**10 对极**、Kt 只有 0.0099 N·m/A —— **1 A 只有 10 mN·m**，转矩极软。用它做位置伺服本身就吃力。
>
> 这件事让我算清了一笔账：**驱动芯片的损耗 = 3 × I² × Rds(on)，只认电流**。低阻电机（<1 Ω）需要大电流，配小驱动板必然过热；而同样的转矩，用高阻电机（5~15 Ω）电流小 4 倍，芯片损耗小 16 倍，代价只是需要更高电压。
>
> 所以结论是：**这台电机的正确用法是"高速低扭"，不是"低速大扭矩"**。下一步我打算换 5~15 Ω 的云台电机。

## 附：白板必写清单

**面试时如果给你白板，这五个东西要能徒手写出来：**

```
1. Clarke：
   iα = ia
   iβ = (ia + 2·ib) / √3

2. Park：
   id =  iα·cosθ + iβ·sinθ
   iq = −iα·sinθ + iβ·cosθ

3. 反 Park：
   uα = ud·cosθ − uq·sinθ
   uβ = ud·sinθ + uq·cosθ

4. 反 Clarke：
   ua =  uα
   ub = −0.5·uα + 0.866·uβ
   uc = −0.5·uα − 0.866·uβ

5. 共模注入：
   共模量 = −(umax + umin) / 2
   三相各加共模量 → 占空比 = 0.5 + u / Vdc
```
