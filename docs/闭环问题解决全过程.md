# FOC 闭环调不通：问题是怎么一步步解决的

> 记录 2026-11-02 ~ 11-04 的调试全过程。
> 起点：位置环"一边有力、一边推开回不来"。
> 终点：位置环和速度环都稳定工作。
> 中间查出 **三个静默错误 + 两处参数标定错误 + 一个安全漏洞**。

---

## 0. 一页看懂

```
现象：位置环逆时针推能弹回，顺时针推就跟着走开，甚至转一整圈
  │
  ├─ 怀疑机械不对称 ──→ 断电手转一圈，阻力均匀 ──→ 排除
  │
  ├─ 怀疑编码器 ──→ 电机在转，但 ch1 恒为 0.000000
  │                 └─→ 【错误(1)】CS 线（PA4）松动
  │
  ├─ 修好线后能读了 ──→ 但闭环还是不对
  │                 └─→ 【错误(2)】每机械圈只有 8192 个计数，不是 16384
  │
  └─ 改对刻度后还差 10% ──→ 【错误(3)】极对数是 10，不是 21
                                 ↓
                          两个 2 倍错误互相掩盖，骗了整整两天
```

---

## 1. 第一层：从"机械"排查

### 1.1 现象

```
逆时针推 → 有明显回弹，能回到原位
顺时针推 → 跟着手走开，松手也不回来，甚至转满一圈
```

### 1.2 当时的推理

控制环的数学是**对称**的：

```c
error = wrap_pi(target - actual);     // 往哪边偏，误差符号跟着变
voltage_q = Kp*error + integral - Kd*speed;
```

误差变号 → 电压变号 → 转矩变号。**两个方向都会被限幅到同样的 ±1.3V。**

**所以"一边有力一边没力"不可能来自代码，只可能来自机械或电气。**

### 1.3 排查

| 检查 | 结果 | 结论 |
|---|---|---|
| 断电手转一整圈，感受阻力 | **均匀** | 不是线缆缠绕、不是齿槽 |
| 通电时两个方向各推一下 | 一边硬一边软 | 有净转矩，但方向不对称 |

**机械排除，回到电气。**

---

## 2. 第二层：编码器读数（错误(1)）

### 2.1 决定性线索

```
电机在转（肉眼可见）
ch1（实测速度）= 0.000000   ← 精确的 0
```

**磁场在转（三相占空比在变）+ 转子在转 + 速度读数为 0 = 编码器读数没有任何变化。**

### 2.2 定位

- `angle_mech` 恒为 0
- 查硬件：**PA4（CS 片选）那根线非常松**

### 2.3 为什么 CS 松了会读数恒 0

SSI 协议靠 **CS 下降沿**启动一次传输：

```
CS 拉低 → 编码器开始吐数据
CS 拉高 → 传输结束，锁存新值
```

接触不良时，编码器根本没被触发，或者读到的永远是同一帧。

### 2.4 教训

> **"电机在转但速度读数为 0"，先查接线，别改代码。**
> 一个松了的接插件能伪装成"控制算法有问题"，浪费一整天。

---

## 3. 第三层：编码器刻度（错误(2)）

### 3.1 现象

修好 CS 线后，读数来了，但**闭环还是不对**。

### 3.2 一个关键的观察

在 `ENC_TEST_MODE = 1`（只读编码器）下慢慢手转：

```
转的角度明显不到一整圈，ch0 就已经从 3.14 走到 6.28
```

### 3.3 真相

```
MT6701 是 14 位传感器
它的原始字段是 0 ~ 16383
但这个字段要转【两整圈】才填满

→ 每机械圈实际只有 8192 个计数
```

而代码里写的是：

```c
float angle_mech = angle_count * 2π / 16384.0f;   // ← 错了一倍
```

**后果：所有角度和速度都只有真实值的一半。**

### 3.4 为什么极其隐蔽

| 特征 | 实际情况 |
|---|---|
| 角度曲线是否平滑 | ✅ 完全平滑连续 |
| 会不会报错 | ❌ 不报 |
| 会不会跳变 | ❌ 不跳 |
| 唯一异常 | **所有数值都小一半** |

**闭环控制拿到"一半"的反馈，会做出一堆看起来像"参数没调好"的怪行为。**

### 3.5 正确写法

```c
#define ENC_COUNTS_PER_REV   8192.0f

float angle_mech = angle_count * 2π / ENC_COUNTS_PER_REV;
```

### 3.6 验证方法（必做）

```
(1) 手转一整圈 → 角度必须走满 0 → 6.283
   只走到 3.14 = 刻度错了一倍
(2) 开环给 1.0 rad/s，转 10 圈计时
   T 应该 = 62.83 / 目标转速（秒）
```

## 4. 第四层：极对数（错误(3)）

### 4.1 现象

刻度改对后，开环 1.0 rad/s 的实测比值是 **0.93 ~ 1.10**，还是差 10% 左右。

### 4.2 排查历史（走了很多弯路）

| 方法 | 得到的结果 | 是否正确 |
|---|---|---|
| 短接两相数齿槽 ÷3 | 21 和 18（两次都不一样） | ❌ 不可靠 |
| 商家口述 | 10 对极 | ✅ **最终确认是对的** |
| 静态步进：转 π/2 电角度看转子走多少 | 算出 21.5 | ❌ 被编码器刻度污染 |
| 开环速度比值 | 0.48 → 算出 20.8 | ❌ 同样被污染 |
| **秒表法：转 10 圈计时** | **算出 ≈10** | ✅ **一锤定音** |

### 4.3 为什么前面的方法全都不对

**因为所有方法都建立在"编码器读数是准的"这个前提上。**

```
速度比值 = 代码极对数 / 真实极对数 × 编码器刻度误差
                          ↑
                    这里藏着一个 2 倍的错
```

**两个 2 倍错误相乘，算出来的结果恰好落在"看起来差不多"的区间：**

| 代码极对数 | 真实 10 + 刻度错一半 | 实测 |
|---|---|---|
| 10 | 10/10 × 0.5 = **0.50** | 0.48 ✅ |
| 21 | 21/10 × 0.5 = **1.05** | 1.06 ✅ |

**这就是"两个错误互相抵消"——每个测量都自洽地错着。**

### 4.4 破解方法：秒表法

```
(1) 开环跑起来，让电机稳定转
(2) 在转轴和固定架上各贴一个标记
(3) 标记对齐时按下秒表
(4) 数满 10 整圈时按停，得到时间 T
(5) 真实机械转速 = 10 × 2π / T
(6) 真实极对数 = 给定角速度 × 代码极对数 / 真实机械转速
```

**为什么它可靠：时间不依赖任何可能标定错的传感器。**

**这是"绝对参考"的力量——当所有传感器都可能错时，用最原始的量（时间、长度、温度）做裁决。**

### 4.5 最终参数

```c
FOC_POLE_PAIRS      = 10
ENC_POLE_PAIRS      = 10
ENC_COUNTS_PER_REV  = 8192.0f
ENC_ELEC_OFFSET     = 0.6627f    /* 极对数改完必须重标，旧值全部作废 */
```

## 5. 位置环：为什么最后只能用纯 P

### 5.1 加了 I 就疯狂震荡

第一次加 `Ki=40`：

```
误差 0.5 rad 时，积分 0.065 秒就打满 1.3V
→ 变成开关控制（bang-bang）
→ 猛冲 → 过冲 → 反向 → 再猛冲
```

### 5.2 降低 Ki、给积分单独限幅，还是震

改成 `Ki=8`，并把积分限幅从 1.3V 降到 0.4V：

```
误差只有 0.023 rad（1.3°）时，ch3 仍然是 -1.300V
```

**说明积分已经涨到限幅，系统仍在开关状态。**

### 5.3 根本原因

```
这台电机 Kt ≈ 0.0099 N·m/A
在 0.1° 的误差下，P 项只能给出 0.05V 的电压 → 推不动（静摩擦）
→ 误差一直存在
→ 积分不停累积
→ 累积到能推动的那一刻，已经是满力
→ 猛冲过头 → 误差反号 → 反向再来一次
```

**这不是"参数没调好"，是"力本来就紧"的物理结果。**

### 5.4 结论

```c
FOC_POS_KP = 5.0f
FOC_POS_KI = 0.0f      /* 关掉 */
FOC_POS_KD = 0.0f      /* 关掉 */
```

**接受 3° 左右的稳态误差，换掉震荡。**

### 5.5 想消掉稳态误差的正确做法

**不要用积分，用摩擦前馈**：

```c
float friction_ff = 0.0f;
if (error_pos >  0.005f) { friction_ff =  0.15f; }
if (error_pos < -0.005f) { friction_ff = -0.15f; }

voltage_q = FOC_POS_KP * error_pos + friction_ff;
```

**区别：前馈是"固定值"，永远不会积到满力；积分是"累加器"，一定会涨满。**

## 6. 速度环：前馈必须重标

### 6.1 现象

目标 6.0 rad/s，实测 6.83，`ch3` 只有 0.10V。

### 6.2 一个反直觉的事实

```
开环时：0.363V 只能跑 0.48 rad/s（一直打滑）
闭环时：0.10V 就能跑 6.83 rad/s（电角度对了，效率高十倍）
```

**闭环比开环高效得多，所以按开环数据标定的 V/f 全都偏高。**

### 6.3 重标方法

用一个实测数据点反推：

```
实测：Uq = 0.101V → 6.83 rad/s
估算摩擦电压：0.05V
→ Uq ≈ 0.05 + 0.0075 × ω
→ 换算成 we = 10ω：Uq = 0.00075 × we + 0.05
```

```c
#define FOC_VF_SLOPE     0.0008f     /* 原来是 0.0020 */
#define FOC_VOLT_OFFSET  0.050f      /* 原来是 0.080 */
```

### 6.4 为什么这样就不震了

```
前馈算准 → 误差接近 0 → P 项几乎不输出 → 不会激发震荡
```

**震荡的根源是"误差太大"，把误差消掉就不震了——不需要靠调小 Kp 硬压。**

### 6.5 最终结果

```
目标 10.0 rad/s，实测 10.16（误差 1.6%）
电压 0.106V，芯片不发热
```

## 7. 顺手发现的安全漏洞

### 7.1 问题

**开环路径没有用 `FOC_UQ_LIMIT` 限幅。**

```c
// 修改前
voltage_q = foc_voltage_vf(speed_e);   // 只受 6.92V 物理上限约束
```

`FOC_VOLTAGE_MAX = 6.92V` 是 **SVPWM 的物理极限**，不是 **芯片散热的极限**：

```
6.92V ÷ 0.54Ω = 12.8A → 芯片几秒就报废
```

**位置环和速度环都有 `FOC_UQ_LIMIT` 保护，唯独开环没有。**

### 7.2 修复

```c
voltage_q = foc_voltage_vf(speed_e);
if (voltage_q >  FOC_UQ_LIMIT) { voltage_q =  FOC_UQ_LIMIT; }
if (voltage_q < -FOC_UQ_LIMIT) { voltage_q = -FOC_UQ_LIMIT; }
```

## 8. 换电机/换编码器时的标准流程

**顺序不能乱，前两步错了后面全白费。**

```
第 0 步  ENC_TEST_MODE = 1，手转一整圈
         ch0 必须走满 0 → 6.283
         只走到 3.14 → ENC_COUNTS_PER_REV 错了一倍
         ↑ 这一步不做，后面全白费

第 1 步  开环 1.0 rad/s，转 10 圈计时
         T 应 = 62.83 / 目标转速（秒）
         或直接看 ch1 / ch0 的比值 ≈ 1.0

第 2 步  ENC_TEST_MODE = 2，读 ch4 → 填 ENC_ELEC_OFFSET
         断电重启复测，两次差 < 0.05 才可信

第 3 步  ENC_TEST_MODE = 0 + 位置环
         推到往反方向跑 → FOC_TORQUE_SIGN 改成 -1.0

第 4 步  位置环稳定后，再上速度环
         先把 V/f 前馈标准，再加 P，最后才考虑 I
```

## 9. 通用经验（比具体参数更重要）

### 9.1 静默错误最可怕

| 错误 | 会不会报错 | 现象 |
|---|---|---|
| CS 线松动 | 不报 | 读数恒 0 |
| 每圈计数错一倍 | 不报 | 所有数值小一半，曲线仍然平滑 |
| 极对数错 | 不报 | 电角度错，闭环永远修不到位 |
| 开环无限幅 | 不报 | 改大目标转速就烧板 |

**它们都不崩、不报错，只是让所有数字悄悄地错着。**

### 9.2 当两个参数都可能错时，找一个"绝对参考"

```
编码器可能错 → 别用它验证别的
速度估计依赖于编码器 → 也别用
→ 用秒表。时间不会错。
```

### 9.3 震荡时先问"前馈对吗"，而不是"增益调小"

```
前馈算准 → 误差小 → P 不用出力 → 不震
前馈算错 → 误差大 → P 拼命补 → 补不够超速，补过头震荡
```

### 9.4 弱电机不要用积分

```
积分是"累加器"，在静摩擦大的系统上必然涨满 → 开关控制 → 震荡
替代方案：摩擦前馈（固定值，不会涨满）
```

### 9.5 拿不准的时候，用手和眼睛

| 问题 | 最土但最有效的方法 |
|---|---|
| 编码器读数对吗 | 手转一圈，看角度是否走满 2π |
| 转速对吗 | 秒表量 10 圈 |
| 有净转矩吗 | 通电推轴，比较两个方向的阻力 |
| 芯片热不热 | 摸一下 |
| 电机堵了没 | 断电手转，感受阻力是否均匀 |

**这些方法不需要任何仪器，但比示波器读数更接近真相——因为它们不依赖任何可能标定错的传感器。**

## 10. 最终生效的参数

```c
/* ============ 电机 ============ */
FOC_POLE_PAIRS       = 10
ENC_POLE_PAIRS       = 10
ENC_COUNTS_PER_REV   = 8192.0f
ENC_ELEC_OFFSET      = 0.6627f

/* ============ 电压 ============ */
FOC_UQ_LIMIT         = 1.30f
FOC_VF_SLOPE         = 0.0008f
FOC_VOLT_OFFSET      = 0.050f
FOC_TORQUE_SIGN      = 1.0f

/* ============ 位置环（纯 P） ============ */
FOC_POS_KP           = 5.0f
FOC_POS_KI           = 0.0f
FOC_POS_KD           = 0.0f

/* ============ 速度环（纯 P + 前馈） ============ */
FOC_SPEED_KP         = 0.15f
FOC_SPEED_KI         = 0.0f
FOC_START_BOOST      = 0.0f
```

**实测表现：**

| 环 | 目标 | 实测 | 误差 |
|---|---|---|---|
| 速度环 | 10.0 rad/s | 10.16 rad/s | 1.6% |
| 位置环 | 5.70 rad | 5.70 ± 0.03 | ~1.7° |

## 11. 还没做的事

| 项目 | 前提 | 价值 |
|---|---|---|
| 空气摩擦前馈 | 无 | 消掉位置环 3° 的稳态误差 |
| 串级控制（位置→速度） | 无 | 推开有阻尼感，抗扰更好 |
| 电流环（L3） | 飞 2 根线 + 配 ADC | 低速平顺、精确限流 |
| 换 5~15Ω 云台电机 | 30~60 元 | Kt 大 4 倍，一切"力不够"的问题消失 |

**这台电机的天花板已经很清楚了：**

```
Kt ≈ 0.0099 N·m/A   → 1A 只有 10 mN·m
Uq 上限 1.3V        → 2.4A → 24 mN·m（散热极限）
→ 任何"靠攒力"的控制机制都会失控
→ 纯 P + 准前馈，是这个硬件上唯一稳定的解
```
